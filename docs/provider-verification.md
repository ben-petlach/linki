# Provider verification before a controlled pilot

This package uses isolated SMTP, IMAP, DNS, and browser fixtures. No real provider account has been connected or used for prospect outreach. Run the checklist below only in a separately approved pilot with owned test identities.

1. Configure a public HTTPS `NEXTAUTH_URL` and strong `NEXTAUTH_SECRET`. Confirm the delivered campaign message contains a visible unsubscribe URL, a `List-Unsubscribe` URL pointing to `/api/unsubscribe`, and `List-Unsubscribe-Post: List-Unsubscribe=One-Click`. A GET must not opt out. A valid POST must stop further dispatch to the recipient across channels; a changed token must fail. Diagnostic SMTP connection checks perform `verify()` only.
2. Check sender DNS readiness. The account readiness endpoint reports SPF and DMARC TXT status, and reports DKIM `unknown` until a selector is supplied. DNS presence alone does not prove correct signing, alignment, reputation, placement, or deliverability. Inspect a received test message for SPF/DKIM/DMARC authentication and alignment before any pilot send.
3. Test SMTP TLS and IMAP TLS with the real provider using the account's own mailbox. Record authentication expiry, disconnect, throttling, and malformed message behavior. The complete IMAP scan must remain stale on failure and resume without losing a planted reply.
4. Test LinkedIn session expiry and checkpoints with an owned account. The runner must stop at authentication challenges or unrecognized layouts and show reauthentication need. No automated challenge or captcha bypass is implemented. Login and runtime now use the browser's actual user agent and the same context options; live compatibility is still unverified.
5. Review bounce evidence. Three distinct hard bounced recipients within 24 hours open a durable hold on that email sender. A repeated DSN for one recipient does not add another distinct failure; other senders remain available. The hold is intentionally conservative and requires an operator decision before resuming. Only DSNs processed during an authenticated IMAP scan contribute to this sender threshold. A recipient hard bounce blocks its exact email address.
6. Complaint events require an authenticated provider adapter. None is configured in this repo. Do not treat arbitrary webhooks or forwarded email as verified complaints. Once a provider adapter exists, a trusted complaint event opens a sender hold immediately and must carry a provider event ID.
7. Test each required provider configuration and mailbox policy independently. Document unsupported OAuth, provider-specific complaint events, and DNS selectors before relying on those capabilities.

The sender hold and LinkedIn session gate run at the final dispatch check. The direct email route also runs the global operator pause at both preclaim and final dispatch checks. A policy change after the irreversible provider call begins cannot retract that call; uncertain outcomes stay held for review.
